4. What still needs to be done

Build list, ordered by how blocking each item is against the handover document. Start at the top.

  1. Step 52 — Reports & Analytics. Executive dashboard (scheduled, completed, in-progress, cancelled, pending, average duration, start delay, attendance). Trip Instance report. Student attendance per Trip ID with timestamps/locations. Driver, bus, and route performance. Recurring schedule performance and exceptions. Audit history for scheduling. CSV exports. Read-only — must not modify operational records.
  2. Admin navigation (spec section 4). Required order: Dashboard → Students → Parents → Classes → Campuses → Transport → Live Tracking → Reports & Analytics → Notifications → Users & Roles → Settings → Audit Logs. Transport submenu: Buses, Drivers, Routes, Stops, Trip Scheduling, Trip Instances. Live Tracking must be a top-level item, not nested under Transport.
  3. Steps 5 + 47 — Campuses. Create/manage campuses and assign students, routes, and trip instances to the correct campus.
  4. Steps 7 + 47 — Classes. Class/grade entities (not free-text grade) and student-to-class assignment for scheduling and reporting.
  5. Step 6 — Academic year / term. Configure academic years, terms, and operating periods.
  6. Step 40 — Audit logs. Record important administrative and operational changes, including scheduling edits, with an Admin Audit Logs screen.
  7. Step 3 — Users & Roles. Admin screen to create users, assign roles, and manage permissions. Add a teacher web route or drop the unused teacher API from the product surface.
  8. Step 30 — Admin Notifications. Real notifications page for transport events. Remove fake header badges (12 notifications / 4 messages).
  9. Step 14 — Dedicated Stops page. Transport → Stops: create, order, assign to routes.
  10. Step 50 — Time-window conflicts. Allow a bus to run multiple morning (or afternoon/evening) trips when times do not overlap. Today the conflict check blocks any second trip in the same period.
  11. Step 50 — Duplicate and schedule audit. Duplicate a recurring schedule. Keep an audit history of schedule changes. Historical completed trips must continue not to be silently rewritten.
  12. Step 18 — Separate pickup and drop-off stops. Configure each student’s pickup stop and drop-off stop independently. Also set home stops for the 2 of 3 students currently missing one.
  13. Steps 35 + 51 — Driver trip history UI. Show assigned and completed trips in the Driver App (API already returns completed trips).
  14. Step 51 — Driver App alignment. Remove ad-hoc Start morning / Start evening that creates trips without a scheduled Trip ID. Allow authorized admin roles to operate a trip. Keep Start/End Morning, Afternoon, and Evening controls tied to the correct Trip ID.
  15. Step 42 — Operational search. Wire the topbar search so it actually filters students, parents, routes, buses, drivers, and trips.
  16. Step 2 — Password change / reset. Self-service password change. Admins can already set a password on create/edit.
  17. Step 41 / 28 / 33 / 34 — Reporting data surfaces. Student attendance per Trip ID, trip history report, and student transport status for the applicable trip (feeds Step 52).
  18. Step 44 — Update smoke tests. Replace ad-hoc trip start with the scheduled Trip ID flow used in production.
